# 角色与交接

| 角色 | 负责 | 边界 |
| --- | --- | --- |
| Dot（Growth Manager） | 决定授权内增长优先级、假设与验收要求；创建任务，审查证据，推进下一步 | 不代替所有者批准实验、数据、产品工程、对外发布、费用或生产变更 |
| Cloud Codex | 接手有明确范围的任务；记录证据／阻塞；独立分支和 PR 交付 | 不自验自并，不擅自扩范围；本次仅文档修订 |
| 本地 Technical Lead | 独立 Review、验证，合并达标的 Harness 文档 PR，合并后复核 | 生产行为合并仍需所有者明确批准；不能把文档通过当成产品上线许可 |
| 所有者 | 明确审批实验、用户研究与数据、产品工程及对外／费用／生产事项 | 沉默不算批准 |

常态流程：Dot 创建与定优先级 → Cloud Codex 接手、提交 PR → Dot 按验收需求判断 → Technical Lead 独立评审、验证并合并达标文档 → 合并后验证记录。首版 Draft 是一次性交付状态，不是永久禁止合并规则。

交接以[持久任务入口](../reports/README.md)为准；连接决策、证据、PR、验收结果。FGH-001 已由仅收到持久任务入口的独立新会话审查者恢复负责人、证据、阻塞与下一步；正式 Technical Lead 新 head 复审仍待完成，详见任务卡。
